# Verification: the iOS App Store's cellular "Ask If Over 200 MB" default, and whether App Store updates re-send an unchanged 723 MB bundled model

Checked on 6 November 2026 against the claims in `store_native_delivery.md` (section 1, "Cellular downloads", and the section 6 gap on delta updates). Apple's developer documentation renders with JavaScript, so it was read from Apple's own JSON feed for the page (`developer.apple.com/tutorials/data/documentation/xcode/...json`). The iPhone User Guide pages were downloaded straight from support.apple.com for each iOS version (17.0, 18.0, 26.0, and the current default, which is the iOS 27 guide). Apple's pages carry no "last updated" date. Each shows "Copyright © 2026 Apple Inc." and was fetched on 6 Nov 2026.

## On iOS 26/27, is the App Store's mobile-data setting still "Ask If Over 200 MB" by default? Do App Store updates re-download an unchanged 723 MB resource in the app bundle, or does Apple's delta update send only changed files?

### Takeaway
**The 200 MB default is not established.** Apple's own iPhone User Guide confirms the option to be asked before downloads over 200 MB for iOS 17 and iOS 18. No Apple page states that this option is the default. The iOS 26 and iOS 27 guides no longer mention 200 MB at all. "Default" rests only on 2019 third-party articles.

**The delta-update part of the claim holds in Apple's primary documentation.** Apple says (page ©2026) that an App Store update package "contains only the content that has changed between versions of your app, excluding any content that didn't change", and that the OS "updates files only if their content changes". So a byte-identical 723 MB model should not be sent again. Two caveats:
- Apple says the store compares against "one or more prior versions", without saying how many.
- A March 2025 Apple Developer Forums report describes a case where deltas failed. In that case resources had changed; the developer's earlier updates, which changed only the executable, did work.

### Cited Findings

**(a) The cellular threshold and its default**
- iOS 17 guide, "Manage App Store purchases, settings, and restrictions on iPhone" (©2026): "Allow app downloads to use cellular data: Below Cellular Data, turn on Automatic Downloads. To choose whether you want to be asked for permission for downloads over 200 MB or all apps, tap App Downloads." — [Apple iPhone User Guide, iOS 17](https://support.apple.com/guide/iphone/manage-purchases-settings-and-restrictions-iph3dfd91de/17.0/ios/17.0)
- iOS 18 guide: the same sentence, word for word. — [Apple iPhone User Guide, iOS 18](https://support.apple.com/guide/iphone/manage-purchases-settings-and-restrictions-iph3dfd91de/18.0/ios/18.0)
- iOS 26 guide, page renamed "Change settings and restrictions in the App Store on iPhone": the 200 MB sentence is gone. Under Settings > Apps > App Store it lists only "Cellular Data: To allow App Store to use cellular, turn on Cellular Data. Adjust other settings for cellular data such as automatic downloads." The same list has a new entry: "In-App Content: Automatically download in-app content in the background before the first time you open the app." — [Apple iPhone User Guide, iOS 26](https://support.apple.com/guide/iphone/change-settings-and-restrictions-iph3dfd91de/26.0/ios/26.0)
- The current default guide (it mentions iOS 27) has the same wording as iOS 26, with no 200 MB figure and no default. — [Apple iPhone User Guide, current (iOS 27)](https://support.apple.com/guide/iphone/change-settings-and-restrictions-iph3dfd91de/ios)
- iPadOS 26 guide: "Cellular Data: (iPad models with Cellular) To allow App Store to use cellular, turn on Cellular Data. Adjust other settings for cellular data such as automatic downloads." It gives no 200 MB figure either. — [Apple iPad User Guide, iPadOS 26](https://support.apple.com/guide/ipad/change-settings-and-restrictions-ipadee10c6e7/26.0/ipados/26.0)
- Apple's support article "Use cellular data on your iPhone or iPad" (fetched Nov 2026) covers turning cellular data on or off per app, roaming and Connectivity Assist. It says nothing about an App Store size threshold. — [Apple Support 109323](https://support.apple.com/en-us/109323)
- A developer post (not Apple staff, September 2022) on Apple's forums names the setting path "General -> App Store -> Mobile Data -> App Downloads". It reports that with "Ask If Over 200MB" set, "Apps over 200MB will not be automatically downloaded" to MDM-managed devices. There are no replies and no Apple response. This shows the option existed in about the iOS 15–16 era. It does not show the default. — [Apple Developer Forums thread 714729](https://developer.apple.com/forums/thread/714729)
- The only sources that call "Ask If Over 200 MB" the *default* are secondary and date from 2019 (iOS 13). — [9to5Mac, 3 Jun 2019](https://9to5mac.com/2019/06/03/ios-13-removes-200-mb-file-size-limit-for-app-downloads-over-cellular/amp/); [MacRumors how-to (undated)](https://www.macrumors.com/how-to/download-large-apps-over-cellular-iphone-ipad/); [iDownloadBlog, 25 Oct 2019](https://www.idownloadblog.com/2019/10/25/about-app-store-cellular-download-limit/)
  - A search-result summary said iGeeksBlog's wording ("this default option triggers the alert message") is ambiguous about which option is the default. The page itself was not opened, so this is weak evidence. — [iGeeksBlog](https://www.igeeksblog.com/how-to-download-apps-larger-than-200mb-using-cellular-on-iphone-ipad/)
- A search for iOS 26-era reporting on a change to the threshold found nothing. Every hit was 2017–2019 coverage of the jump from 150 MB to 200 MB and of iOS 13's new options. — [TechSpot, 2019](https://www.techspot.com/news/80324-apple-raises-ios-cellular-download-limit-first-time.html)

**(b) Delta updates for an unchanged resource**
- Apple, "Doing advanced optimization to further reduce your app's size", section "Reduce the size of app updates" (undated, ©2026). The old Technical Q&A QA1779 ("Reducing Download Size for iOS App Updates") URL now redirects (HTTP 301) to this page; checked with curl on 6 Nov 2026.
  - "Instead of always downloading the whole app when an update to the app is available, the App Store creates an update package. It compares one or more prior versions of your app to the new version and creates an optimized package. This package contains only the content that has changed between versions of your app, excluding any content that didn't change."
  - "This comparison looks at everything in the application bundle, including the application executable, storyboards, nibs, localizations, and other assets, like images."
  - Advice: "Don't make unnecessary modifications to files." "Store content that you expect to change in an update in separate files from content that you don't expect to change." "Don't rely on the creation and modification dates of files in your application bundle. The operating system updates your app using the update package, and updates files only if their content changes. It doesn't update files because of changes to metadata; for example, the creation and modification dates."
  — [Apple Developer Documentation: Doing advanced optimization to further reduce your app's size](https://developer.apple.com/documentation/xcode/doing-advanced-optimization-to-further-reduce-your-app-s-size#Reduce-the-size-of-app-updates)
- Same page, on-demand resources: "When you upload your app to App Store Connect, asset packs don't become part of your app's initial download or app updates." — [same page](https://developer.apple.com/documentation/xcode/doing-advanced-optimization-to-further-reduce-your-app-s-size)
- Counter-evidence: a developer report on Apple's forums (March 2025) about a Unity app with an IPA of about 2.2 GB.
  - Versions 1.0.1 and 1.0.2 changed only the executable, and their updates "consistently completed within 30 seconds, even over a mobile network".
  - Version 1.1.0 changed 311 files (513 MB) and added 417 (166 MB). It "triggered" "a full download of 2.4 GB", shown in a download-confirmation dialog, where the developer expected only about 679 MB.
  - An App Store Connect Engineer (Apple staff) asked for a Feedback Assistant ticket. No cause or fix is posted.
  — [Apple Developer Forums thread 777442, Mar 2025](https://developer.apple.com/forums/thread/777442)
- Secondary (August 2025, iOS 17 screenshot): with Low Data Mode on, the App Store "shows you the exact size of an app update for your device, often a tiny fraction of the listed app size". This is a practical way to measure Nota's real update size on a phone. — [Gingerbeardman blog, 6–7 Aug 2025](https://blog.gingerbeardman.com/2025/08/06/ios-low-data-mode-reveals-true-app-update-sizes/)

### Inferences
- **The claim as written in `store_native_delivery.md` section 1 should be softened.** Apple's guides (iOS 17 and 18, the versions most of Nota's iOS 16–25 fallback users run) confirm that an "ask before downloads over 200 MB" option exists. Calling it the default is supported only by 2019 secondary sources. For iOS 26/27, Apple's guide no longer names any threshold, so even the 200 MB figure has no primary support on current iOS.
- What can be said safely: on the iOS versions Apple documents (17–18), an ~0.9 GB install over mobile data either triggers a confirmation prompt or is allowed outright, depending on the user's App Downloads choice. Nobody has documented whether a hard block exists on iOS 26/27, and the 2019 coverage says the prompt can be accepted.
- **Update cost of bundling is acceptable in principle.** Per Apple's primary doc, an app update that leaves `hohe-w8.onnx` and `punct-w8.onnx` byte-identical should not resend them. The 2025 forum case fits this: executable-only updates of a 2.2 GB app finished in under 30 s on mobile data. That is exactly Nota's situation when only Dart code changes.
- Nota-specific conditions (my inference; no source covers Flutter specifically):
  - The model files must stay byte-identical across builds. They should be committed, or copied in from a pinned, hashed artifact, rather than re-exported or re-quantized per build. ONNX export and quantization may not give the same bytes twice.
  - They must keep the same path under `App.framework/flutter_assets/`.
  - Splitting Hohe into several external-data files would make a future partial model change cheaper. This follows Apple's "separate files" advice, but whether the update package diffs whole files or bytes inside a file isn't documented.
- **Model updates under bundling** likely resend the whole changed file (about 723 MB). A re-quantized model changes nearly every byte, and Apple doesn't document byte-level diffing within a file.
- **Users several versions behind** may get a bigger package or the full app. Apple says only "one or more prior versions", not all of them.
- **Bundling is all-or-nothing across OS versions.** As far as I know, app thinning makes variants per device, not per iOS version. So "bundle as a fallback for iOS 16–25" would also put the 840 MB inside the app for iOS 26+ users, which defeats an Apple-hosted Background Assets pack for them. A deferred path for older iOS (ODR, or a self-hosted download) avoids this. This inference was not checked against an Apple source.
- The new iOS 26 setting "In-App Content: Automatically download in-app content in the background before the first time you open the app" is very likely the user-side switch for Background Assets packs, which matters for the Apple-hosted path (`store_native_delivery.md` section 5). Apple's guide doesn't name Background Assets here, so this is inference.

### Gaps
- **No Apple primary source states the default value** of the App Downloads (cellular) setting on any iOS version. Settling it needs a fresh iOS 26/27 device or simulator: Settings > Apps > App Store > Cellular Data > App Downloads, after an erase-and-reset.
- No primary source on whether the iOS 26/27 menu still offers a 200 MB option, a different figure, or none. The guide's wording changed and gives no threshold.
- No primary source on whether the cellular prompt for an **update** is judged on the update package size or on the full app size. In the 2025 forum case, the dialog showed the full 2.4 GB only because a full download was triggered.
- No source on how many prior versions Apple builds delta packages against, or whether diffs are whole-file or binary within a file.
- No source explains why deltas failed in the 2025 Unity case, so it is unknown whether any Flutter build habit (for example, re-signing or the file layout) could cause the same failure. Nota could check by shipping two TestFlight or App Store builds with only a Dart change and reading the update size in Low Data Mode (secondary method above).

## What exactly do the primary sources say (quote them), and how current are they?

### Takeaway
Only two kinds of Apple primary source apply. (1) The iPhone/iPad User Guides: these quote the 200 MB option for iOS 17–18, never give a default, and drop the figure for iOS 26/27. (2) Apple's Xcode documentation: it quotes delta updates that contain "only the content that has changed". Both were fetched on 6 Nov 2026 and are undated (©2026). Everything that says "Ask If Over 200 MB is the default" is a 2019 secondary article and predates 2024.

### Inferences
- For the decision in `store_native_delivery.md`, the delta-update question can be treated as answered by a current Apple primary source: unchanged files aren't resent. Keep a note that one real-world failure was reported in 2025 and that Nota should measure its own updates.
- The cellular-default question stays **not established** for iOS 26/27. For the iOS 16–25 fallback population, the strongest supportable statement is: "Apple's iOS 17–18 guides document an option to be asked before App Store downloads over 200 MB on cellular; which option is the default isn't documented by Apple." The report should not say "by default" without attributing it to 2019 third-party articles.

### Gaps
- Apple publishes no change log or dates for these support pages, so it can't be shown when the 200 MB wording was removed (somewhere between the iOS 18 and iOS 26 guides). The removal may reflect a menu change or only a rewrite of the guide.
- No Apple Platform Deployment or MDM documentation was found that names the App Downloads cellular setting or its default. The 2022 forum post suggests there is no MDM key for it.
